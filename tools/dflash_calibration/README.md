# Fresh TP2 DFlash K/V capture

These source tools do not launch or reconfigure a model. The operator must first
approve and record a separate runtime contract. Old diagnostic scripts and
captures remain historical evidence; do not execute them as the repaired path.

The hook requires an explicit source revision, runtime-definition SHA256, unique
capture ID and rank. Python startup exits if installation fails. Loaded-rank
receipts contain source and hook hashes, container PID and boot identity.
The request driver verifies both receipts before any POST, including its canary.

Actual context and query writes carry rendered input IDs, original positions,
sequence IDs, scheduled boundaries and physical slots. Rejected and padded rows
are excluded. Eager execution, no async scheduling and one isolated sequence are
capture-only contracts. These tools do not change serving settings.

A client error leaves observation leases active. Successful requests can release
them only after both producers report completion without an active batch or
failure receipt. No client timeout automatically stops a model.

The exporter requires every fixture, layer, rank and phase in each stage. It
checks saved tensors against event maxima and refuses an artifact after heldout
overflow. It writes only ten local-layer FP32 K/V scales using the observed-data
formula. Q and original weights are untouched.

CPU contract checks: run test_contract.py with the project's verified virtualenv.
The actual observer and native FP8 reload still require separately authorized
runtime checks. Source repairs do not establish calibrated quality or throughput.

The shared image carries these inert tools at
/opt/vllm-runner/tools/dflash_calibration. No Docker ENV enables the hook.
An approved calibration definition must opt in on both ranks with matching
runtime and capture identities. Do not reuse the exited diagnostic definitions.
